# Planned: character reference design step before asset generation

Stated by the user on 2026-08-01 as future work, not implemented.

## The idea

Add a new step **before** art asset generation: design and approve a
**character reference sheet** per character, then generate everything else
against it.

Example given: a coworker character named Janet — generate her front view,
side view, and portrait, check that the three read as the same person, and
only then start generating the other assets (scene plates, character states,
cover).

## Where it slots in

`.agents/documents/art-system.md`, section "Submitting a pack", currently:

1. copy manifest template
2. generate assets with `PROMPT_TEMPLATE.md`
3. fill in filenames, composition, provenance
...

The new step goes between 1 and 2: one reference sheet per `castId` named in
the story's Step 2b cuts, generated from the Step 3 character card
(Persona + Character), consistency-checked, then used as the identity anchor
for every later generation.

## Why it matters here

The existing pack gate already asks for "consistent identity, clothing, line
work, lighting, and camera across states" — but it checks that *after* the
assets exist, so a drift failure costs a full regeneration. A reference sheet
moves that check earlier and makes it cheap.

It also gives the Step 9 "Character agreement" check something stable to walk
the trait table against, instead of judging identity from whichever single
state happened to be drawn.

## Decided 2026-08-01

- **Location:** `stories/<story>/reference/`. The sheet is idea material, not
  shipped implementation — it stays out of `app/` and out of the pack
  manifest, consistent with the `stories/` = idea, `app/` = implementation
  split.
- **Views required:** front, side, portrait, back, plus the expression states
  the brief calls for. The full set, not the three originally named — back
  view pins hair, clothing, and silhouette that front and side leave
  undefined; expression states match what the pack actually ships.
- **Nature of the check — user's clarification, and the important part:** the
  reference sheet is *not* primarily a human review artifact. It is an
  **image generated by AI to align every later image of the same character**.
  The alignment is mechanical: later generations are anchored to the sheet, so
  identity consistency is produced rather than inspected. If that anchoring
  proves stable, the step can run **without human supervision**.

  This changes the shape of the step. It is not a gate in the sense that
  `character-separation-gate.md` is a gate — it is a generation input that
  happens to make the existing art review gates pass by construction. Do not
  write it up as a pass/fail human review checklist.
- **Binding mechanism:** deferred until tested. Whether the sheet is passed as
  an image input to later generations, or distilled into locked text in
  `PROMPT_TEMPLATE.md`, depends on what the current image tooling actually
  honours. Same posture as Step 7b takes on TTS prompting: record the intent,
  test, then write the recipe.

## Still open

- What "stable" means concretely — the evidence that would justify dropping
  human supervision, and whether anything checks the sheet itself before it
  becomes the anchor.
- Whether a failed anchoring (later art drifting off the sheet) is caught by
  the existing `art-system.md` review gates or needs its own signal.
