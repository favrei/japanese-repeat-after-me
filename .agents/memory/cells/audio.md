# Reference Audio and TTS

Canonical memory for the reference audio a learner imitates: how it is
generated, which voice and tooling produce it, how it is bundled and cached,
and what remains unsettled about prompting the synthesiser.

## Current belief

- Reference audio is **generated at authoring time and bundled**, not
  synthesised per playback. Browser `speechSynthesis` is a runtime fallback
  only, never the authoring target. This avoids voice and pronunciation drift
  across browsers and devices. See [Content](content.md).
- Before 2026-07-30 the PoC's playback was in fact browser `speechSynthesis`,
  not a bundled model. That has been replaced.
- Reference audio quality is a learning-critical asset, not decoration: a
  mispronounced clip teaches the mistake. Every clip must be judged by ear
  before it becomes a learner reference.

## Selected tooling

- **Qwen3-TTS** is the first practical local replacement: official Japanese
  support, 0.6B and 1.7B variants, Apache-2.0, and voice control/cloning.
- Generation runs locally on the Apple M3 through **`mlx-audio` 0.4.6** on
  MLX/Metal, using the **1.7B CustomVoice 6-bit** model and the native Japanese
  speaker **`Ono_Anna`** from the official CustomVoice config.
- Model weights stay in the Hugging Face user cache and are never committed.
- Authoring tooling lives under the nested PoC's `tools/tts/`.

Measured during selection on the M3:

- first 0.6B 8-bit sample: 3.84 s of audio, 4.45 s processing, 4.34 GB peak;
- final 1.7B batch completed on the M3;
- six normalized MP3 autoplay assets total about 160 KB.

Later comparators, not selected:

- **GPT-SoVITS** — MIT code, Japanese support, 5-second zero-shot cloning,
  Apple Silicon MPS. Useful once a consented Japanese reference voice exists.
- **Style-Bert-VITS2 JP-Extra** — Japanese specialist, but its code and
  default-model terms plus voice-specific workflow need separate release
  review.

## Reproducibility

The generator pins MLX model snapshot
`1c6c0ff58c43afa8df571facde2efa077efd85e2`, `mlx-audio==0.4.6`,
`huggingface-hub==1.26.0`, and a per-line stable seed. Regenerating a single
line (`ordering-menu`) reproduced the batch clip's SHA-256 exactly
(`f0265af4e902d66a50a06f26f006cdba73a9d2715286436820971aeed26e8e8d`).

Preserve this property. Record the model version, speaker, exact instruction
text, and seed alongside generated clips; without the prompt text a later
re-tune cannot separate a bad prompt from a bad model or a bad sentence.

## Prompting is unresolved

- The useful Qwen3-TTS CustomVoice instruction levers, their wording, and how
  strongly they bind have **not** been tested. There is no established recipe.
- The first batch used per-line acting instructions and the user rejected it
  for a "weird pant sound". Qwen can turn expressive direction into breaths or
  other non-verbal performance, which is unacceptable in pronunciation
  reference audio.
- **Decision:** acting instructions are removed from the canonical generator
  path; all six clips were regenerated with the clean native `Ono_Anna` preset.
  `--instruct` is experiment-only and requires listening QA.
- The stage authoring flow therefore captures delivery *intent* in plain words
  rather than prescribing prompt text, and explicitly does not block stage
  authoring on this question. See [Content](content.md).
- Settling the prompt format and lever set needs its own experiment. See
  [Experiments](experiments.md).

## Voice verdict and parking

On 2026-07-30 the user accepted the local-generation plumbing but judged the
Qwen3 voice itself still "a little bit gross". **Do not spend more time tuning
that voice until the parallel story-design line is ready**, so the desired
character and voice direction can be evaluated together. Voice identity is part
of the character persona, not an isolated audio setting. See
[Content](content.md) and [Visual Design](visual-design.md).

(`Add locally generated Japanese reference audio`), which includes:

- pinned MLX authoring tooling under `tools/tts/`;

## Verification and its limits

- `npm run qa` passed typecheck, build, and all 13 tests with only the
  pre-existing font lint warning.
- A production-browser timed check found bubble 1 still active at 3 s and
  advanced by 6 s, matching the 5.4-second canonical clip, with no console
  warnings or errors.
- A read-only browser attempt to inspect `caches.keys()` failed because the
  browser-test evaluation scope did not expose the Cache API (`caches` was
  undefined). This is a tooling limitation, **not** a service-worker or app
  failure: every MP3 was served with HTTP 200 and the service worker source
  pre-caches all six paths. A true offline reload remains a useful manual or
  device QA step.

## Gotchas

- Run the generator's compile check from `tools/tts/`, or pass
  `tools/tts/generate_audio.py`. Running `py_compile generate_audio.py` from
  the PoC worktree root fails on path, not on code.

## Open questions

- What prompt format and lever set should the canonical generator use?
- Which voice fits the eventual character persona, once story design is ready?
- Should the learner's reference lines use a different voice from the other
  party's?
- Which words does the synthesiser reliably mispronounce (counters, numbers,
  katakana loanwords, names, 何 readings), and how are those handled?
- How is per-bubble audio versioned when a stage's text is revised?
- When a consented human Japanese voice exists, does cloning replace the
  preset voice for released chapters?
